# Agent IR implementation plan

## Goal

Create an independent sibling Git repository for an internal, versioned Agent IR and a narrow Claude Code → Agent IR → Codex conversion slice. Reuse the semantics already documented in the local conversion skills and the generated artifacts, without changing those repositories.

## Design

- Use Pydantic v2 `BaseModel` types as the canonical IR, with runtime validation, serialization, an explicit version, and `model_json_schema()` support.
- Model identity, prompt, semantic capabilities/restrictions, model intent, delegation, execution boundaries, lifecycle hooks, and provenance/extensions. Retain original source frontmatter and document text to support future Claude → IR → Claude round trips.
- Keep harness-specific parsing/rendering in adapters registered behind separate source and target protocols.
- Return structured diagnostics with mapping status, category, authority effect, field path, and whether safe emission is blocked. Distinguish functionality loss from authority changes.

## Security policy

- Exact semantic mapping emits normally.
- An inexact mapping may emit only when the rendered target is proven to have an effective capability set that is a subset of the source; report the narrowing with a structured diagnostic.
- If a safe subset cannot be established, report the authority uncertainty/increase and block runnable target emission.
- Never treat increased authority as an ordinary lossy conversion or silently broaden permissions.

## First vertical slice

- Parse Claude Code Markdown subagent definitions, including YAML frontmatter, tool allowlists, model fields, hooks, permission metadata, and unknown custom fields.
- Render Codex standalone custom-agent TOML, preserving the prompt and identity. The renderer must account for Codex's lack of an arbitrary per-agent tool allowlist and require enough information about the enforced target tool boundary to prove safe emission.
- Provide a small CLI, focused fixtures/tests, and an architecture document covering the internal-only status and how another adapter is added.

## Acceptance checks

- Validate malformed input and IR values; preserve unknown source metadata and source text.
- Test exact mapping, safe narrowing with diagnostics, authority uncertainty blocking output, model handling, and real fixture expectations that are not generated by the implementation.
- Run the test suite and static syntax/type checks available in the new repository.

## Scope

Claude Code and Codex adapters are included now. OpenCode, OMP, Mistral Vibe, and Hermes adapters are future work and require semantic verification before implementation. Re-verify Claude/Codex semantics before expanding those initial adapters. This IR remains an internal implementation format, not a proposed universal standard.
